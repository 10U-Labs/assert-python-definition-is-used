# Explain plainly before dense prose

When the user says they do not understand, the answer is to start again from
the beginning in plain language with one concrete example. It is not to
restate the same explanation at the same density with more detail attached.

This was learned across one session on issue #1, where "i dont understand"
was said twice before the explanation dropped to a function, a comment
mentioning it, and the observation that the tool searches for the word,
finds it in the comment, and stays quiet. That landed at once. The two
explanations before it had been accurate and had failed, because each
answered a narrower question than the one being asked while keeping the
register of the documents it was describing.

The pull toward that register is real and worth naming. This repository
writes in dense formal prose, in its issues and in the files in
`.claude/memories/`, and that is right for a document read slowly and wrong
for a conversation. Matching it while explaining is mistaking the subject
for the medium.

So lead with the smallest concrete example that shows the behaviour, one
idea per paragraph, and stop to check before layering on caveats and design
alternatives. Offering a choice the reader has no basis to make is a form of
the same error: in this session, being asked which of two independent edits
to do first was a question that did not need asking.
